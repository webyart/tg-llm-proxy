# tg-llm-proxy v1.49.3

## A reserve that answers nothing gets one more try

- A small local reserve can return HTTP 200 with an empty `content`. The fallback wrapper now repeats the reserve attempt exactly once when the failure is `ErrEmptyAnswer`, for `Complete` and for `Stream` (a stream only when no non-empty delta has reached the caller — an empty delta is not text on the screen, so it does not block the retry and never causes duplicated text).
- Tests cover both paths and assert that the reserve is called exactly twice and the fallback outcome is recorded as `ok`.

## Single-model endpoints are adopted at startup

- STRATA loads one model at a time. When `GET /v1/models` lists exactly one model whose name differs from `STRATA_MODEL`, the bot adopts that name for the primary client and logs a `WARN` with both names. An unavailable listing, several models or an empty list keep the configured name — discovery never guesses in an ambiguous case.
- This keeps the primary path real instead of quietly sending every request through the fallback; on this machine the bot now logs the switch from `qwen3.8-flash-next-coder-iq1_m` to the loaded `qwen3.8-flash-next-iq3_s`.

# tg-llm-proxy v1.49.2

## A 200-with-error is reported with its reason

- LM Studio (and some OpenAI-compatible servers) can answer HTTP 200 and put the failure into an `error` object in the body while a model is loading. The client reported `strata answered 200: client error, not retried`, which hid the reason and sent the reader to the wrong layer. `APIError.Error` now prints the sanitized, truncated body for exactly that case; 4xx/5xx keep their short class text and never echo a provider body.
- Diagnosed from a live incident: the primary STRATA endpoint was stopped (connection refused on :8080) and the LM Studio reserve answered 200-with-error because its 27B model was still loading; the fallback itself was configured correctly (:1234) and streams fine once the model is resident.
- Test `TestAPIErrorKeepsTheProviderBodyOfA200` covers both branches.

# tg-llm-proxy v1.49.0

## Fallback-модель

- Две необязательные ENV-строки, по умолчанию пустые: `STRATA_FALLBACK_MODEL` (пусто = fallback выключен) и
  `STRATA_FALLBACK_BASE_URL` (пусто = endpoint `STRATA_BASE_URL`). При заданной fallback-модели отдельный base
  обязан быть absolute http(s) URL без userinfo; та же модель на том же endpoint отклоняется как ошибка
  конфигурации.
- `internal/model/fallback.go` оборачивает основной клиент. `Complete` повторяет запрос один раз на fallback после
  retryable-ошибки (5xx/429/transient/network); `Stream` повторяет только пока ни один delta не дошёл до
  вызывающего, поэтому частично доставленный ответ никогда не переигрывается. 400/401/404 и ошибка разбора
  возвращаются без fallback.
- Метрика `model_fallback_total{outcome="ok|error"}` и одно структурированное предупреждение на попытку с именами
  обеих моделей; при двойном отказе ошибки обеих попыток объединяются без тел ответов и ключей.
- Wrapper не реализует transcription: голос по-прежнему идёт через основной клиент. `/model` показывает список
  основного endpoint, а явно выбранная fallback-модель продолжает работать как per-chat выбор без отдельного
  сохранения fallback-состояния.
- Config rows: 63 → 65. Тесты покрывают primary 500 → fallback 200, primary 400 → без fallback, двойной 500,
  stream до первого delta и после него, выключенный fallback, а также отсутствие ключа и текста тела в ошибках и
  логах.
- Живая проверка: основной клиент смотрел на мёртвый порт (сетевая ошибка), резервный — на реальную STRATA;
  в логе появилось `model fallback attempt ... reason=network`, ответ пришёл от резервной модели («Да»). Прод
  пока работает без fallback (`STRATA_FALLBACK_MODEL` пуст) — включим, когда вторая модель докачается и получит
  стабильное имя.

# tg-llm-proxy v1.48.0

## Hybrid RAG: embeddings + FTS5

- Migration 016 adds `rag_chunk_embeddings` (one float32 little-endian vector per chunk and model, cascading with
  its chunk) and an index on `(chat_id, model)`; schema version is now 16.
- `internal/embed` is a small OpenAI-compatible client (POST `{base}/embeddings`, batches of at most 64 inputs,
  one vector length per response, no key or input text in an error) with a cosine helper and its own tests.
- Four optional config rows, all off by default: `RAG_EMBEDDINGS_ENABLED`, `RAG_EMBEDDINGS_BASE_URL`
  (`http://host.docker.internal:1234/v1`), `RAG_EMBEDDINGS_MODEL`
  (`text-embedding-nomic-embed-text-v1.5`) and `RAG_EMBEDDINGS_TIMEOUT_SECONDS` (10, 1..120).
- `/docs add` embeds the chunks of the new document after the store commit; any failure is a warning and the
  document stays stored and lexically searchable.
- Search mixes the query vector into the existing ranking: `final = (1-w)*lexicalNorm + w*cosine`, `w = 0.4`.
  Chunks the lexical query never matched are scored when they are among the 64 closest by cosine; a chat without
  vectors gets exactly today's lexical result. A failing embedding server logs one warning and degrades silently.
- `cmd/ragembed` backfills existing databases (`-path`, `-base-url`, `-model`, `-chat`, `-batch`), idempotent and
  exiting non-zero only when nothing could be embedded.
- Metrics `rag_embeddings_total{outcome="ok|error"}` and `rag_embedding_dimensions`.
- `rag_quality_test.go` gains a hybrid paraphrase case: the lexical call returns nothing, the hybrid call ranks the
  right chunk first; the existing lexical thresholds stay green.

## Turn-aware context window

- `BuildMessages` groups history rows into turns (a user row opens a turn, the assistant rows after it belong to it) and includes a turn whole or drops it whole instead of cutting per message. A window can no longer start with an assistant message, and an answer is never sent to the model without its question.
- The newest turn is the exception: its question always survives (cut to the remaining budget when needed), while its assistant rows are cut or dropped first. The persona remains the first system message and is counted against the budget.
- Eight table-driven tests cover the cut-in-the-middle turn, a one-rune budget, orphan assistant prefixes, multiple assistant rows per tool-loop turn, persona accounting and unchanged `MAX_INPUT_CHARS` truncation.

## Message ordering when the next question arrives mid-answer

- A streaming placeholder (or draft) keeps the position where the answer started, so a final edit could leave the answer ABOVE a question typed while the answer was being produced. The dispatcher now counts admitted incoming messages per chat; if the next one arrived during the stream, the finished answer is sent as a new message below it and the placeholder is removed. Callbacks (approvals) do not count as a new turn.
- `STREAM_DRAFTS_ENABLED` (default false) makes Bot API draft previews opt-in: a draft cannot be deleted from the chat, so it stays at its starting position until Telegram expires it. The edit path remains the default.

## RAG candidates ranked by SQLite

- RAG lookup asks SQLite for the best FTS5 `bm25()` matches (limit 300) instead of scoring a wide slice in Go; document-name matches keep a reserved place and an invalid FTS expression degrades to the name search. Benchmark on 10k matching chunks: ~2–3× faster, 32× less memory, 30× fewer allocations. No migration.

## Testing

- Unit and integration suites are run in the Docker test image (`docker build --target test`, `docker run … go test`), not by executing `webapp.test` on the Windows host.

## Reliability (Sprint 1)

- Watchdog стрима больше не может заблокировать чтение: отправка «пульса» стала неблокирующей, а при сработавшем watchdog цикл выходит немедленно. Раньше узкая гонка оставляла горутину, слот модели и per-chat lock занятыми до рестарта; регрессионный тест воспроизводит прежний дедлок.
