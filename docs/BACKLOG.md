# BACKLOG

Задачи, отложенные по просьбе владельца. Формат: проблема → ожидаемое поведение → критерий готовности.

## UX: создание задачи блокирует интерфейс

**Проблема (2026-11-11).** В Mini App после нажатия «Создать» интерфейс блокируется на всё время генерации плана: `CreateTask` синхронно ждёт ответ STRATA (десятки секунд), кнопка/форма недоступны, прогресса нет. Пользователь видит только «выполняется» уже после создания.

**Ожидаемое поведение.**
- `POST /api/tasks` отвечает быстро: задача создаётся в статусе `planning`, план генерируется фоновой горутиной/воркером.
- UI сразу показывает карточку «План готовится…» с возможностью отменить; форма разблокирована.
- Ошибка планирования переводит задачу в `failed` с понятной причиной и кнопкой «Повторить план», а не молчаливый таймаут.
- Telegram `/task` получает тот же асинхронный путь (не блокирует dispatcher на минуту).

**Критерий готовности.**
- p95 ответа `POST /api/tasks` < 300 мс при живом STRATA.
- UI не блокируется, виден статус `planning` и отмена.
- Тест: медленный fake-модельный клиент (5 с) не задерживает HTTP-ответ; план появляется позже; failed-план ретраится.
- Метрика `bot_tasks_planning_seconds` и алерт на >120 с.

**Приоритет:** высокий (следующий UX-спринт после provider/cost).
